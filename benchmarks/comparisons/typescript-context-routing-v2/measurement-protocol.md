# Repaired routing: declared measurement protocol

This version implements the scope in [protocol.md](protocol.md). It qualifies
the unchanged routing policy on the repaired shared tool surface, and never
rescores routing-v1 or combines its measurements with this batch.

## Version and immutable inputs

Comparison, measurement, report and replay identity is
`typescript-context-routing-v2`. Raw adapter traces retain
`typescript-context-explore-v1`; exact source and delivery formats are unchanged.
The new tools and observer are the versions published with repair commit
`c14b2a87a8dde6543c7c790888619bad94711430`. The whole source tree is pinned to that
commit; extractor remains 25. All earlier frozen harnesses remain byte-identical.

The original v3 seventeen-case corpus, snapshots, gold, model, reasoning level,
environment controls, hard budgets, source/relationship scoring and fourteen
numerical gates are unchanged. Both A and B use the repaired fourteen-tool
repository capability; both have the same three resource helpers. B alone adds
the unchanged 1,155-byte policy prefix. The new prompt manifest binds all
seventeen A/B pairs. The schedule is 102 serial attempts in alternating AB/BA
order, with three repetitions per case and arm.

## Observation and qualification

The actual runner uses the new MCP tools and new observer. Host events preserve
raw arguments, including null defaults; matching adapter records contain the
effective integer arguments. Valid `item.completed`/`status: failed` and
`item.failed` failures retain exact native error costs and zero source. Missing
or malformed evidence remains unknown. A failed first type-dependency call
still records route selection but fails initial source exposure. Later recovery
is counted separately and cannot change that result.

Exact native outputs must match the next model request. Source proof requires
the requested native anchor, matching snapshot file hash/content and exact
trace span. Names and relationships alone do not prove source receipt. Partial
source can establish receipt and is separately marked incomplete; unchanged
required-source recall still governs delivered context.

A `keep` requires the unchanged numeric `keep`, all nine initial B maintained
source exposures, complete routing/measurement evidence, and independent replay
of all 102 attempts. A known exposure or numerical failure rejects an otherwise
complete batch. Missing measurement, unknown routing or incomplete replay makes
qualification inconclusive. All thirteen type-route cases and four call-target
controls are also reported. Gold is evaluator-only and never enters prompts.

All observed calls and source-free helpers count. Error/recovery payload bytes,
policy input, total input, cached input, output and elapsed time remain charged.
No scheduled attempt is selectively retried, replaced or excluded. Any partial
or failed attempt stays visible, even if its final answer is correct.

The published byte-limit proof remains repair evidence. A separate
`measurement-transport-verification.json` exercises this version's actual
`run_attempt` entrypoint for A and B with explicit null byte limits, real
Codex/MCP and a scripted loopback Responses endpoint. It checks effective
prompts, identical repaired schemas, actual A/B identity, exact native payload
delivery, source proof and complete observed accounting. It makes zero provider
calls and does not measure model adoption.

After environment/authentication/catalog checks and offline transport pass,
commit and publish all qualification code and preparation evidence. Then create,
publish and validate a separate freeze recording that code commit, the pinned
source, every harness/corpus/comparison hash, prompt/policy/schema identities,
model catalog and complete plan. Only then collect provider outcomes.

Replay reconstructs fresh indexes, checks all frozen identities and native
payloads, and recomputes source, relationship, routing and numerical evidence
from retained raw events. Its verification must cover every planned attempt.
Publish the independent result, numerical gates, exposure evidence and limits.
Parent acceptance remains conditional on all requirements; shared-runtime
promotion and multilingual W4 remain separate.
