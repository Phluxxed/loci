# Loci R0: indexing architecture and ablation seams

Assessment only. Source checkout: `f41b3eaa4c7871c68972de5f760572a6bcbe1760`, inspected 2026-10-22. This note maps implemented mechanisms and candidate independent cuts. It does not implement a cut, change product architecture, or claim a measured quality effect. The existing dirty R0.1 work was left alone. Source links below refer to this checkout; design documents describe original intent, not proof of current utility.

## Actual cold, warm and changed-file paths

1. **Cold normal request:** MCP calls `service.retrieve(... ensure_fresh=True)`. `ensure_fresh_index` sees no index, takes a per-repo refresh lock and calls the indexer ([mcp_server.py:218](../../src/loci/mcp_server.py#L218), [service.py:521](../../src/loci/service.py#L521)). The indexer checks root overlap, scans/hashes every eligible file, loads all control/extension inputs, parses symbols and semantic observations for every source, constructs language indexes, resolves full graph, validates, mirrors sources, writes JSON and catalog ([service.py:167](../../src/loci/service.py#L167), [service.py:2222](../../src/loci/service.py#L2222), [service.py:402](../../src/loci/service.py#L402), [index_store.py:276](../../src/loci/storage/index_store.py#L276)). Retrieval then loads and validates that graph and packs selected source/proof ([service.py:1203](../../src/loci/service.py#L1203)).
2. **Warm normal request:** `ensure_fresh_index` still scans/hashes eligible source and recomputes graph-input hashes; if unchanged it does not index, but `_load_graph_context` loads whole JSON and reconstructs/validates graph state before either `retrieve` or `read` ([service.py:521](../../src/loci/service.py#L521), [service.py:1891](../../src/loci/service.py#L1891), [service.py:2133](../../src/loci/service.py#L2133), [service.py:1230](../../src/loci/service.py#L1230)). Exact source expansion thus pays semantic graph validation despite needing a contained/hash-bound source span; the previous scalpel review profiled this cost on one checkout and explicitly did not establish a latency distribution ([scalpel review:81](../../docs/reviews/2026-09-29-scalpel-review.md#L81)).
3. **Changed or explicit incremental index:** Existing schema/graph must validate to be reusable. The scan hashes all files; equal-hash files reuse symbols plus raw import/export/reference/call/type observations and diagnostics. Changed files re-run the separate parses. Control/profile changes may invalidate graph resolution or force Markdown reparse. Regardless of the number of changed files, Loci rebuilds the language indexes, resolves/materializes the graph against all observations, and rewrites full mirror/JSON/catalog ([service.py:181](../../src/loci/service.py#L181), [service.py:211](../../src/loci/service.py#L211), [service.py:266](../../src/loci/service.py#L266), [service.py:402](../../src/loci/service.py#L402), [index_store.py:276](../../src/loci/storage/index_store.py#L276)). Thus “incremental” means parse reuse, not graph or persistence delta updates.

## Why these mechanisms exist

The June graph design followed a graphify trial where a bare-name cross-file call was asserted as certain and distorted pathfinding; it proposed a strict no-fabricated-edge trust rule, directed relations and provenance ([graph-layer design:11](../../docs/design/2026-06-10-graph-layer-design.md#L11), [graph-layer design:35](../../docs/design/2026-06-10-graph-layer-design.md#L35)). This justifies resolution discipline and explicit unresolved states; it does not prove that every current language-specific edge family improves normal source retrieval. The July design aimed to centralize a generic graph substrate for code and domain consumers, with declarative profiles and external data contributions; its cited wiki benchmark showed naive graph retrieval and large envelopes were harmful ([extensible design:12](../../docs/design/2026-07-13-extensible-graph-retrieval-design.md#L12), [extensible design:34](../../docs/design/2026-07-13-extensible-graph-retrieval-design.md#L34), [extensible design:90](../../docs/design/2026-07-13-extensible-graph-retrieval-design.md#L90)). The coverage/store plan separately required maintained tests, explicit uncertainty, cheap inventory and recoverable writes ([coverage plan:3](../../docs/plans/2026-07-30-loci-trustworthy-coverage-and-store-lifecycle.md#L3), [coverage plan:19](../../docs/plans/2026-07-30-loci-trustworthy-coverage-and-store-lifecycle.md#L19)).

These are design motivations, not an R0 outcome measure. The prior scalpel review found concrete source-selection and traversal-admission defects, plus costly exact reads, while keeping a boundary around what its one-off probes demonstrated ([scalpel review:19](../../docs/reviews/2026-09-29-scalpel-review.md#L19), [scalpel review:52](../../docs/reviews/2026-09-29-scalpel-review.md#L52), [scalpel review:81](../../docs/reviews/2026-09-29-scalpel-review.md#L81)). No indexing-family ablation result is claimed here.

## Independently bypassable candidate mechanisms

For a deterministic ablation, compare against the same source snapshot, language corpus, query set, freshness policy, output contract and separately isolated store. Keep a mechanism off from extraction through materialization, persistence and request-time consumption; merely hiding delivered edges leaves its indexing costs intact. Preserve source hashes, exact spans, coverage, stale-handle behavior and necessary validation in every condition. The items below are seams, not prescribed product removals.

| Candidate cut | Minimum coherent intervention | Dependency / interpretation qualification |
| --- | --- | --- |
| External graph profiles + contributions | Bypass `load_graph_extensions`, profile-field Markdown reparse, profile/contribution loops in `materialize_graph`, their input hashes and diagnostics ([service.py:257](../../src/loci/service.py#L257), [materialize.py:77](../../src/loci/graph/materialize.py#L77), [materialize.py:450](../../src/loci/graph/materialize.py#L450)). | Independently testable for code-context work; domain/wiki consumers may require it. Normal native-only traversal suggests potential redundancy for ordinary code lookup, not universal redundancy. |
| Type observations, resolution and edges | Return no type observations at the extraction seam; omit `resolve_type_relations`, type projection and type validation while keeping import/reference records for other consumers ([type_observations.py:69](../../src/loci/parser/type_observations.py#L69), [materialize.py:397](../../src/loci/graph/materialize.py#L397)). | Could reduce a separate parse and substantial resolver work. May remove relationship paths to authored types; requires evaluating type-context tasks, especially Python/Go/Rust/TS. |
| Call sites, resolution and edges | Skip call extraction in the shared import batch; omit `resolve_calls`, call validation and projection ([imports.py:196](../../src/loci/parser/imports.py#L196), [materialize.py:377](../../src/loci/graph/materialize.py#L377)). | Shared parse still needed for imports/references, so this is not a full-parser saving. Calls consume resolved references; bypass can leave reference capability intact. |
| Value references / local exports | Skip reference batch and resolver/projection while preserving import extraction; adapt call and type resolution to their documented inputs or pair cuts when they cannot retain meaning ([imports.py:179](../../src/loci/parser/imports.py#L179), [materialize.py:302](../../src/loci/graph/materialize.py#L302)). | A naive `raw_symbol_references=()` cut changes calls/types indirectly; independent effect needs the consumers controlled or a precise upstream contribution boundary. |
| Import relationships and language module resolution | Test native import-edge delivery off separately from module-control resolution off. For the latter, omit the Go/JS/Cargo/Swift control loaders/builders plus import/reference resolution paths they enable ([service.py:240](../../src/loci/service.py#L240), [service.py:402](../../src/loci/service.py#L402), [materialize.py:267](../../src/loci/graph/materialize.py#L267)). | Import edges are a small delivery cut; control resolution is a larger capability cut that can affect references/calls/types. Language-specific cuts are cleaner than one all-language flag. Swift modules and Go/Rust synthetic nodes may also alter anchor selection. |
| Graph enrichment only | Existing trusted `RetrievalRuntime(graph_enrichment=False)` stops after shared anchor/source packing ([service.py:1182](../../src/loci/service.py#L1182), [retrieval.py:83](../../src/loci/retrieval.py#L83)). | This isolates traversal/response enrichment only: graph extraction, freshness, load and validation remain. Do not label it a no-graph-engine condition. |
| Graph engine as a whole | Experimental source-only path would need an explicit index/storage/request adapter that preserves source discovery, exact reads, coverage and freshness without requiring `GraphIndexState`; current `_load_graph_context` hard-requires and validates graph state ([service.py:2133](../../src/loci/service.py#L2133)). | This is a distinct large ablation, not achieved by the existing enrichment flag. It tests whether semantic indexing is justified by the normal workflow and costs. Do not infer result from the previous graph-on/off pilot. |
| Full source mirroring / full graph validation on exact read | Isolate persistence mirror strategy and read-time validation separately, using exact live-file containment/hash checks or validated snapshot state as replacement contracts ([index_store.py:306](../../src/loci/storage/index_store.py#L306), [service.py:1230](../../src/loci/service.py#L1230)). | Both are potential cost centers but also integrity mechanisms. A timing-only cut that weakens stale-source refusal is not a valid comparison. |
| Diagnostic surface and usage analytics | Remove from an experimental client exposure independently of normal MCP and basic CLI; `mcp_server` already separates surfaces ([mcp_server.py:193](../../src/loci/mcp_server.py#L193), [mcp_server.py:728](../../src/loci/mcp_server.py#L728)); usage analytics lives in `IndexStore` ([index_store.py:549](../../src/loci/storage/index_store.py#L549)). | Tests tool-discovery burden and maintenance, not source retrieval quality. External operators may still rely on health, verify, repair and diagnostics. |

**Current judgment:** source spans/coverage, stale-source checks and provenance validation are justified by the trust contract and actual read path. Repeated full scan/hash, full graph reconstruction on exact reads, multi-parse changed files, full mirror rewrite and general extensions are concrete cost or duplication candidates. Their necessity for *normal* code-context work is unproven from architecture alone. The cross-language resolver families are substantial, independently identifiable capability bundles whose benefit should be measured on tasks that need their specific relationships. The current code and historical reviews do not justify deleting any family outright.

## Limits of this note

This is a source and design-doc trace, not a runtime benchmark or consumer census. Loci's own initial exact-file retrieval returned partial coverage, with a subsequent targeted read of source files used for the path map. No tests or shared-store mutations were run for this assignment. The old review's timings and graph pilot belong to an earlier revision; they are context for candidate seams, not current R0 measurements.
