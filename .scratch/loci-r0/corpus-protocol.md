# R0 deterministic corpus ablation protocol (pre-run)

Date 2026-10-22. These are **new mechanism diagnostics** against serving source `f41b3ea` with unchanged frozen corpus inputs. They are not repetitions, rescoring, or replacements of historical model experiments.

- Worktrees: `.worktrees/r0-control` compares `service.retrieve(..., graph_enrichment=True)` baseline with `False`. `.worktrees/r0-ownership` compares the unchanged baseline with a process-local `_ownership_lifts` override returning no representative members only when the expanded node kind is file/package/crate/module. Symbol-to-native-owner lift and anchor owner identity remain intact. No production source edit.
- Corpus: TypeScript v3 17 cases via `load_corpus(root=.../typescript-context-v3)`; multilingual 19 via `load_inputs()`. Their archive SHA, per-file hashes and gold intervals are checked by the existing loader/materializer. Each snapshot is freshly indexed in its worktree-specific isolated store; setup time is recorded apart from retrieval. The current engine is applied to the archived data; the corpus's historical engine pin remains provenance, not a current-engine equality assertion.
- Request: for every case, match its gold anchor's file, name, kind and contained frozen byte span to exactly one indexed symbol using the existing endpoint matcher. Use that exact `seed_ids=[id]` in both arms with empty query. If the gold anchor is source-only, use its exact file path in both arms. Ambiguous/missing matches are retained as case failures, never silently resolved by name. This intentionally gives the retrieval the gold anchor; it tests expansion after discovery, **not** ordinary discovery or agent behavior.
- Score: every packet source must match archived whole-file SHA, bytes and interval. Normal `relationships` plus `sources` are adapted in memory to the existing TypeScript and multilingual `score_relationships` exploration proof input (no persisted scorer changes). `_covered` on packet source intervals counts each frozen required context span. For each case retain required/covered source counts, all-source flag, available/delivered relationship counts and integrity violations, forbidden proof, packet/usage bytes, graph work counters, omissions, full raw packet and three wall/CPU timings. Normal packet schema validation is separate. Incomplete source/proof cannot receive credit. No hydration occurs, so large required spans may remain uncovered despite a valid `source_ref`.
- Order/limits: index all snapshots before measurements; execute all baseline requests first, then intervention requests, each three timed repetitions, fixed case order and the product's unchanged packet limits. Repeated calls use the same indexed snapshot/store and yield warm-path timing; a fixed order can bias timing, so latency is descriptive only. The first successful packet and every failed/partial attempt are retained. No models, agents, provider usage or shared catalog/store changes.
- Decision boundary: a source/proof coverage gain or loss diagnoses this one fixed request on a selected corpus. Graph relationship delivery is capability evidence, not evidence an agent used it or finished a task. A real utility or provider-cost claim requires separately authorized matched task work and independent grading. Existing negative/qualified results remain frozen.

## Adapter correction after first retained control pass

The first control output is retained at `corpus-control/`. It exposed two input-adapter issues, not product changes. The normal packet legitimately includes structural `imports`/`imports_type` edges, which the historical semantic scorers define outside their semantic gold. The corrected in-memory scorer adapter filters only those structural edges before calling each existing relationship scorer; **all** original relations remain in each raw packet and every relation's source IDs are still checked. The frozen Markdown case's `Limits` section does not match an indexed symbol in current `f41b3ea`; both conditions now use the exact `guide.md` file request and retain that fallback identity. No other missing/ambiguous gold symbol is guessed. The corrected run is a new output directory, `corpus-control-v2/`; the first pass is not overwritten or silently counted as a scored result.

The v2 control and first ownership runs timed `service.retrieve`, which loads and validates graph state on every call. Those outputs are retained as fresh-service observations. The scoped architectural ablation requires the graph already loaded, so the final direct runs call `retrieval.retrieve_context` with an identical preloaded `store/nodes/state/coverage` per snapshot and put indexing and graph preload/validation in separate setup fields. This matches the direct retrieval used in existing controls while avoiding an inference that graph loading cost is traversal cost. Final outputs are `corpus-control-direct/` and `corpus-ownership-direct/`; all earlier outputs remain visible.
