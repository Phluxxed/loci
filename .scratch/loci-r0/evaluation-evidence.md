# R0 evaluation evidence map (read-only assessment, 2026-10-22)

**Disposition.** R0 can run controlled deterministic ablations on current code and authored fixtures. These can establish whether a change preserves source truth, improves targeted source/proof delivery, and changes packet size or local runtime. They cannot establish that an agent finishes more tasks or spends fewer provider tokens. The native R0.1 path is qualified for task-assistance execution/readback, but no measured native-versus-Loci pilot has run; the first pilot still lacks its prospective freeze and task-level bindings. The corrected [native qualification](../../docs/reviews/2026-10-22-r0-1-native-qualification.md) supersedes the old custom-sandbox gate in the [earlier inventory](../../docs/reviews/2026-10-22-r0-1-harness-qualification.md). Do not treat the earlier gate as a current blocker.

## Historical measured evidence and what it warrants

- **Ordinary normal retrieval:** the frozen eight-row Anvil adoption result was 8/8 Loci invocation and 6/8 positive graph delivery, yet only 5/8 all-facts answers and five cost-gate failures; binding/browser positive delivery was 2/4 against a 3/4 bar. The primary binding check failed to deliver a stored proof, while the browser check delivered its expected call. Reconciliation later found some old truncation classifications too pessimistic, without changing the frozen value result. This supports investigating selection and complete delivery, **not** claiming graph is useless or useful from delivery alone. [Result](../../docs/reviews/2026-09-14-normal-graph-adoption-result.md), [diagnosis](../../docs/reviews/2026-09-14-normal-graph-repair-diagnosis.md).
- **Later binding repair:** v4's two agents received 43 relationship records across seven retrieves, but neither supplied all compound facts and median gross input was 1.5325× original baseline (382,041 vs 249,298). Uncached input was nearly equal; the excess was largely cached input. Elapsed and visible bytes passed their frozen gates. This is a negative ordinary-value result for that selected pair, not graph-only causality or a revised score for earlier runs. [Result](../../docs/reviews/2026-09-15-schema-repair-token-result.md).
- **Multilingual workflow:** 114 scheduled attempts replay; 51 had complete accounting, 44 exact answers, 11 full passes. Only the single Markdown task passed the full quality/cost gate. The programming-language comparisons were mostly withheld because of incomplete graph accounting and asymmetric source access, especially Go/Cargo controls. Those packets still expose concrete source/relationship coverage gaps. [Result](../../docs/reviews/2026-09-13-multilingual-workflow-measurement.md), [defects](../../docs/reviews/2026-09-13-multilingual-measurement-defects.md).
- **Computation/storage:** small fresh fixture indexing median was 0.019788 s (114 cases), while whole adapter work median was 41.877 ms A / 50.715 ms B; these are different operations and do not isolate storage. Older stage-3 anchor and stage-4 traversal whole-call means were 61.29 and 114.380 ms, and stage-6 1,116-symbol/611-edge indexing was 1.299 s full / 1.156 s no-change. None is a current full-repository source-read or graph-loading distribution. [Cost review](../../docs/reviews/2026-09-13-storage-cost-decision.md). The exact-read single profile above is stronger evidence for a specific repeated-work question than these broad, mixed-operation averages.

## Minimal deterministic experiment recipe

1. Pin one serving source revision, target snapshot/file hashes, request list, limits and gold **before** replay. Use fresh isolated `LOCI_BASE_DIR` per branch or a byte-identical copied index; never share a mutable store or write to historical results. Preserve both successful and failed/empty/partial outputs. A command that indexes or invokes an agent is not read-only; inspect its implementation before use. `graph_anchor_stage3.py` indexes its corpus, and stage 4 builds a temporary mirror/store, so neither is a harmless score-only command.
2. Make one conceptual change per ablation, reuse the same request and source. For the built-in graph-off control, use the production `RetrievalRuntime` seam and the existing equality/negative tests. For source selection, use literal-shadow plus exact path/ID/ambiguity controls. For packet composition, use accepted normal retrieval source/proof gold and the retained binding target, checking full model-visible envelope rather than a backend edge count.
3. Record per-request target-source recall/completeness and evidence validity first; then omissions and uncertain/false relations; then complete envelope/source bytes and elapsed including cold versus warm state. If a candidate saves bytes by losing a necessary exact span, proof or safety check, it fails that fixture even if faster. Repeat timing only to resolve variability and separate index/setup/read costs.
4. Interpret each result at its level: a deterministic fixture can justify or refute an architectural mechanism for that fixture. A user-value claim needs independent full-task gold and matched agent work; R0.1's proposed two-task pilot would remain selected developmental evidence even if launched. Preserve all prior freezes and scores.

**Recommendation to the primary:** prioritize the built-in graph-on/off and source-selection controls, then a focused exact-read computation probe if that cost is part of the architectural judgment. The hard truth boundaries—content hashes, exact extents/continuation, stale-handle rejection, complete proof and honest omissions—are justified by tests and failure records. Broad normal ownership/member expansion is questionable where it consumes output before direct target proof; prior binding evidence shows the mechanism. A blanket deletion of parsers/resolvers, graph diagnostic capabilities, or storage redesign is unproven by these fixtures; consumers and phase-attributed cost would have to justify it. Extra agent campaigns are not required for this deterministic R0 assessment.
