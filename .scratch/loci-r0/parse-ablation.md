# R0 parse-tree reuse ablation

**Assessment:** Identical grammar + source bytes were parsed repeatedly within one indexing operation. Reusing the resulting tree removed about two thirds of backend parse calls on the frozen snapshots without changing persisted semantic state or sampled normal packets. It did **not** demonstrate a material end-to-end indexing gain: the paired instrumented aggregate improved 1.3%, and the large Anvil pair changed direction across order reversal. The separate semantic extractors and AST walks remain necessary to produce their respective records; this experiment bypassed only repeated parsing.

Source checkout `f41b3eaa4c7871c68972de5f760572a6bcbe1760`. Disposable code is [r0_parse_reuse.py](parse-driver.py). Serving source was unedited. Raw data: [full JSON](parse-full.json), [full stdout](parse-full.stdout), [Swift/error JSON](parse-swift-edge.json), [Swift/error stdout](parse-swift-edge.stdout), [focused parser checks](parse-focused-tests.stdout). All source roots and `LOCI_BASE_DIR` stores were temporary and isolated.

## Mechanism tested

`service._index_repo_unlocked` hashes source, then calls `parse_file` for symbols, `extract_import_batch` for imports/exports/references/calls, and `extract_type_observations` for authored type sites ([service.py:266](../../src/loci/service.py#L266), [service.py:306](../../src/loci/service.py#L306), [service.py:340](../../src/loci/service.py#L340), [service.py:381](../../src/loci/service.py#L381)). The first uses language-pack `get_parser(grammar).parse(bytes)`; the others use `Parser(get_language(grammar)).parse(bytes)` ([extractor.py:74](../../src/loci/parser/extractor.py#L74), [imports.py:163](../../src/loci/parser/imports.py#L163), [type_observations.py:120](../../src/loci/parser/type_observations.py#L120)). The type extractor explicitly keeps a separate semantic pass because declaration ownership differs from executable ownership ([type_observations.py:69](../../src/loci/parser/type_observations.py#L69)). Swift package-manifest parsing also uses `get_parser("swift")` ([swift_modules.py:251](../../src/loci/graph/swift_modules.py#L251)).

The experiment monkeypatches only the two parser factories *during one `index_repo` call*. A facade checks the exact `tree_sitter.Language` equality and exact byte sequence. Control always calls the real `parse`; reuse returns a cached `Tree` on a matching subsequent request. Both arms execute the original extractors, syntax contexts, error checks, resolvers, graph materializer and validators. Both arms use the same facade instrumentation. The cache is cleared at operation exit ([experiment:87](parse-driver.py#L87), [experiment:152](parse-driver.py#L152), [experiment:188](parse-driver.py#L188)).

The installed factories were inspected before wrapping: `tree-sitter 0.25.2` and `tree-sitter-language-pack 1.15.8`; `get_parser` delegates to its Rust extension. `get_language("python")` returns distinct but equal/hash-equal language objects, suitable for an exact grammar key. The package factory called the patched parser constructor internally, so the facade detects an already wrapped parser and avoids counting it twice. A `Tree` supports `.edit()`, but no source consumer in `src/loci/parser` or the Swift manifest parser calls `.edit()`; this is an observed read-only-use precondition, not a general immutability guarantee. The wrapper refuses incremental parses or changed signatures rather than caching unsafely. The language-pack `process` fallback in `parse_file` is outside this cache and was not separately instrumented ([extractor.py:68](../../src/loci/parser/extractor.py#L68)).

## Controlled measurements and equality

The frozen multilingual inputs contributed 16 snapshots/19 cases; TypeScript v3 contributed 15 snapshots/17 cases, including the real Anvil source snapshot. Both corpora verify archive and file hashes when materialized ([multilingual inputs:53](../../benchmarks/multilingual_context_inputs.py#L53), [snapshot materializer:19](../../benchmarks/typescript_context_corpus.py#L19), [snapshot materializer:90](../../benchmarks/typescript_context_corpus.py#L90)). Every snapshot had two paired passes: control→reuse, then reuse→control. Stores were fresh for each arm. A separate deliberate malformed TypeScript + invalid UTF-8 Python repository was included in the full run. An additional focused edge repository added `Package.swift` and Swift source, which the frozen corpus did not cover.

| --- | ---: | ---: | ---: | ---: | ---: | --- |
| Multilingual 16 snapshots × 2 | 32 | 296 / 296 | 94 | 202 | 1.676 / 1.576 s | all indexes equal |
| TypeScript 15 snapshots × 2, incl. Anvil | 30 | 1,084 / 1,084 | 378 | 706 | 41.271 / 40.811 s | all indexes equal |
| Malformed/invalid UTF-8 | 1 | 8 / 8 | 3 | 5 | 0.024 / 0.024 s | index + packet equal |
| **Total full run** | **63** | **1,388 / 1,388** | **475** | **913** | **42.971 / 42.411 s** | **63/63 full indexes equal; 17/17 sampled packets equal** |

The aggregate CPU times were 41.947 s control and 41.423 s reuse, a 1.25% difference. Measured backend `parse` wall was 1.223 s control and 0.425 s reuse: about 0.797 s saved in the inner parse calls, compared with 0.560 s saved across all index operations. The median per-pair index wall ratio was 0.980; tiny fixtures have millisecond-scale differences and should not be read as a stable speedup. The Anvil snapshot alone requested 455 parses per operation and reused 294 of them (161 unique trees). Its instrumented control/reuse walls were 19.728/19.909 s in the first order and 20.817/20.200 s in the reverse order. One candidate run was slower and one faster. The observed graph, source-copy and JSON work still dominates.

The full persisted `index.json` objects were compared recursively with **no normalization**: symbols, hashes, all raw/resolved graph records, edges, coverage, diagnostics, schema/version fields and path were field-for-field value equal for every pair. Representative `service.retrieve(... ensure_fresh=False)` packets were compared on eight selected snapshots per repetition plus the error fixture: 17/17 equal after excluding only opaque store-local `source_ref` and `next_source_ref` IDs. Packet `snapshot`, source, relationships, omissions and usage remained in the comparison. The malformed/UTF-8 pair retained two `GRAPH_SOURCE_UNPARSED` and two `GRAPH_TYPE_EXTRACTION_FAILED` diagnostics in each arm; no partial graph records were promoted. The additional Swift edge run had 13 control parse requests, five unique reused parses, eight hits, identical full index and packet; it covers the manifest factory path but is too small for a timing claim.

The focused existing parser checks passed under the reuse facade: malformed TypeScript type-site diagnostic, Unicode UTF-8 byte interval, stale Python source-hash rejection and malformed Python import rejection ([test_type_observations.py:292](../../tests/parser/test_type_observations.py#L292), [test_type_observations.py:145](../../tests/parser/test_type_observations.py#L145), [test_python_type_observations.py:89](../../tests/parser/test_python_type_observations.py#L89), [test_imports.py:904](../../tests/parser/test_imports.py#L904)). The first test command used a nonexistent pytest node for the fourth check; it was corrected and passed. The retained test log shows both attempts.

## Cost and conclusion

All wall/CPU figures above were measured with `tracemalloc` enabled and parser-facade counters in **both** arms. They are paired experiment timings, not uninstrumented production latency; do not compare Anvil's roughly 20 s here to another run's absolute wall. Python-traced peak heap on Anvil was about 269 MB control and 322 MB reuse, roughly 53 MB higher while the cache was live. The cache retained 161 exact-byte keys totaling 1.91 MB of source bytes at operation end; trees and their backing allocations account for further retention, but `tracemalloc` does not cover all C allocations and this is not a total-RSS measurement. The cache is operation-local and cleared before the next index. The measurement does not cover a long-lived cache, concurrent requests or warm exact reads.

**Classification:** repeated backend parsing of identical grammar and bytes is redundant computation, but keeping three semantic extraction passes is justified by distinct output/ownership rules and was held constant here. Parse-tree reuse is **questionable as a product simplification or priority**: it saves inner parser work but adds live memory and yielded no robust whole-index gain on the measured corpus. A parser-wide rewrite, merger of AST walks, or deletion of any semantic family is **unproven** by this experiment. No production integration is recommended from this evidence alone.
