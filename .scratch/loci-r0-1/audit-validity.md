# R0.1 validity audit: complete-work harness

Read-only audit of `benchmarks/complete_work/{accounting,evidence,evaluate}.py`, their controller/control seams, independent oracles, and `tests/test_complete_work_*.py`. This qualifies reusable machinery for a proposed paired native-tools versus current-Loci pilot; it does not validate a new campaign or its host telemetry. Loci source retrieval for `evaluate.py` returned partial static coverage with preview/output omissions, so the conclusions below use direct complete-file reads for the named files.

## Reusable capabilities

- `accounting.summarize` differences thread-cumulative token usage once across turns, rejects invalid/nonmonotonic values, marks absent stage updates and interrupted captures unknown, and separates nested item counts from raw outer calls. Unique `rawResponse/completed` identities are explicitly only a lower bound for model requests (`accounting.py:17-27,29-76,98-168`; `test_three_turn_cumulative_usage_is_differenced_once_and_duplicate_update_is_free`, `test_missing_nonmonotonic_and_foreign_thread_usage_never_become_zero`, `test_interruption_retains_partial_usage_without_claiming_a_complete_total`). `arm_cost` enforces the expected run-ID set, complete usage/correctness/latency, includes failed runs in totals, and returns infinite per-correct cost at zero success (`accounting.py:171-191`; `test_arm_cost_includes_failed_rows_and_retains_zero_success_and_missingness`, `test_arm_cost_rejects_missing_duplicate_and_unexpected_scheduled_rows`). The existing `orientation`/`downstream` phase grouping assumes the `orient`/`implement`/`continue` three-turn campaign (`accounting.py:149-163`).
- The controlled Loci server retains exact returned and backend packets plus content-addressed full source versions. It validates claimed source extents against retained source at capture, and `load_receipts` rechecks artifact sizes/hashes and contiguous receipt sequence (`control.py:203-247,268-311,382-410,610-643`; `test_receipt_validation_turns_a_bad_extent_into_a_retained_failure`). `summarize_delivery` then matches successful native `mcpToolCall` items to exact tool, arguments, and returned packet, and treats absent, duplicate, conflicting, failed, or unpaired evidence as unknown (`evidence.py:43-93,124-151,210-329`; `test_unmatched_ambiguous_and_missing_native_mcp_telemetry_are_unknown`, `test_identical_receipts_are_not_double_counted_and_unpaired_native_marks_its_stage_unknown`, `test_extra_or_failed_native_mcp_items_stay_unknown`). Packet/source/proof counts describe delivery, not model reliance or provider tokens (`evidence.py:330-349`). This join is specific to the Loci MCP server and its two tool names (`evidence.py:18-28,60-66,115-136`); a native-tools arm needs a different evidence adapter and cannot inherit `delivery.status == known` by assumption.
- `evaluate_episode` restores stage-specific source blobs, checks each blob hash, produces diffs, and runs an evaluator outside the measured turn (`evaluate.py:13-46,49-101`). Loci's oracle uses child processes importing the candidate checkout, fresh stores, pinned dependencies, independent path/index probes and focused tests (`oracles/loci.py:1-6,36-78,281-438`; `test_baseline_fails_and_reference_patch_passes`, `test_oracle_rejects_targeted_regressions`). Anvil's oracle uses a fixture outside the target checkout, pinned source/lock and Node environment checks (`oracles/anvil.py:1-6,49-105,140-218`). Both oracles are task-specific; neither scores a generic native retrieval task. `evaluate_episode` deliberately leaves overall `correct` unset for arm-blinded review (`evaluate.py:59-62,96-100`).

## False-valid or missing-evidence risks

1. **Terminal token usage is not proven complete.** A stage becomes `known` after *any* positive usage delta and a completed outcome; `summarize` does not require a terminal usage update, reconcile a final thread total, or relate usage updates to later `rawResponse/completed` events (`accounting.py:63-76,104-115,136-143`). An in-memory journal with one usage update followed by two response completions returned `usage_status: known` and only the early token total. This is a conditional undercount risk if the native host can omit or delay its final usage notification; existing tests cover wholly missing, nonmonotonic, and interrupted usage, but not this partial-success case (`tests/test_complete_work_accounting.py:67-112,212-219`). **Smallest repair before a cost claim:** establish the live host's final-usage contract, then require a checkable terminal usage boundary (or mark usage unknown when finality cannot be proved). Preserve the raw journal.
2. **Receipt identity is weaker than artifact identity.** `load_receipts` validates packet/source artifacts and sequence, but does not bind receipt `arm`, `target_root`, `config_sha256`, or operation metadata to the run config (`control.py:610-629`). `summarize_delivery` accepts mixed `arm` values with `arm: null` while its `status` can still be `known` if packets match (`evidence.py:238-257,329-344`). Thus a wrong/mixed receipt directory containing matching calls, or modified receipt metadata, can be reported as known delivery. This is an analysis-integrity gap, not evidence that historical receipts are corrupt. **Smallest repair:** at join, compare every receipt's control identity with frozen run configuration and require exactly one expected arm; return unknown on mismatch. Retain existing artifact and pair validation.
3. **Anvil oracle can pass an incomplete result shape.** The fixture runner checks only that `checks` is a list of dictionaries, then uses `all(checks[*].passed)`; an empty list passes, and a nonempty `errors` list does not prevent `status: passed` (`oracles/anvil.py:209-218`). The fixture normally emits named checks (`oracles/anvil_creation_evidence_fixture.mjs:111-183`), but a truncated/corrupted output with `{"checks": []}` can silently pass; current Anvil tests cover source/environment/CLI availability and syntax, not this result validation (`tests/test_complete_work_anvil.py:13-73`). **Smallest repair:** require the fixed expected check-ID set exactly once and no fixture errors before passing; add one malformed-output test. This matters only if reusing that Anvil oracle.
4. **Stage snapshot manifests lack readback binding.** `source_snapshot` creates `sha256` over its file map and stores that identity in the stage row (`controller.py:37-66,267-269`). `restore_snapshot` verifies each referenced blob, but `evaluate_episode` does not recompute the file-map hash or compare it to the controller stage identity before evaluating (`evaluate.py:13-27,58-95`). A changed manifest that points to other valid retained blobs can be graded as a different candidate. **Smallest repair:** verify manifest hash and stage identity on readback; reject mismatch before oracle execution. This is an output-corruption risk, not an observed failure.

## Qualification boundary

The existing campaign fixes a Terra/high three-turn thread, graph-on/off Loci tools, two historical targets, and task-specific oracles (`benchmarks/complete_work/README.md:3-13,28-45,110-125`). Its README explicitly says no campaign freeze or measured outcomes are present, and a prior sandbox probe failed, so this audit cannot qualify a live pilot host or prove token completeness (`README.md:3-6,61-82`). A paired native-tools comparison needs frozen equal instructions/permissions, a separately defined native evidence path, independent task criteria, and a live telemetry check before attributing relative cost or quality. The focused accounting/evidence/integration checks passed: `17 passed` with `.venv/bin/python -m pytest -q tests/test_complete_work_accounting.py tests/test_complete_work_evidence.py tests/test_complete_work_integration.py`. No paid model turns or production retrieval edits were made.
