# R0.1 corpus and paired protocol: native navigation versus current Loci

**Status:** protocol proposal and historical-source inventory only. No native-versus-Loci run, corpus freeze, or model outcome is claimed here. Keep all cited historical controls, source maps, gold, and results unchanged.

## What the retained evidence permits

- The complete-work design is a *graph-on/off* design, explicitly not a frozen campaign or result. Its control keeps Loci's anchor selection, source paging, tool names, and shell access in both arms, varying graph enrichment throughout an episode. Its two task types, three sequential prompts, independent behavioral checks, and source identities are reusable; its treatment/control implementation and graph-specific causal claim are not. [design protocol:3-35](../../benchmarks/complete-work/design-v1/protocol.md#L3-L35), [episodes:9-55,98-179](../../benchmarks/complete-work/design-v1/episodes.json#L9-L179), [control:143-186](../../benchmarks/complete_work/control.py#L143-L186)
- The historical TypeScript corpus pins 17 source-comprehension cases and gold authored before endpoint preflight. Fourteen are mechanism/control fixtures; three maintained tasks come from one Anvil snapshot. Its source identities and exact-answer checks are useful *diagnostics*, but these prompts were constructed around Loci's type-context gaps and do not sample ordinary code work. The v3 observed-call denominator superseded v1/v2 causal declarations prospectively; no historical result may be silently rescored. [v1 corpus:3-7,18-35,37-63](../../benchmarks/corpora/typescript-context-v1/README.md#L3-L63), [v3:3-24](../../benchmarks/corpora/typescript-context-v3/README.md#L3-L24)

Neither is a native-versus-current-Loci comparison. Preserve delivery/attribution caveats and frozen scoring. ## Minimum proposed paired protocol

1. **Estimand and arms.** Compare the *assignment to ordinary native repository navigation* with *assignment to the current normal Loci `loci_retrieve`/`loci_read` availability plus the same native navigation*. The agent chooses its normal navigation within each arm; keep Loci non-use, failed calls, and empty/partial packets. Pin Loci's serving commit and two-tool schemas separately from target source. Do not call graph-off the native arm. A Loci-arm benefit would estimate the effect of this availability/instruction/tool package, not graph-only causality, use of the first packet, or internal model reliance. The historical design already warns that delivery is not reliance and that selecting only graph-positive episodes biases the result. [design:17-35](../../benchmarks/complete-work/design-v1/protocol.md#L17-L35)
2. **Freeze before model turns.** Name a new protocol and hash the prompts, full target exports/file map, applicable instructions, runtime and dependency lock, current serving implementation, tool descriptors, limits, independent oracle, schedule, and scoring code. Put rubric, gold, prior answers, benchmark files, and other arm's workspace beyond either agent's access. Both arms get the same source commit, ordinary shell/file access, model/effort, agent instructions except the necessary Loci tool availability and invocation directions, writable test area, dependency environment, stage caps, and follow-up prompts. The extra Loci descriptors and discovery work are part of treatment and must be recorded, not hidden from cost. Preserve source IDs and all hashes with each run; pre-index the Loci copy and report setup/index time separately. [design:66-102,168-194](../../benchmarks/complete-work/design-v1/protocol.md#L66-L102), [README:28-45,76-82](../../benchmarks/complete_work/README.md#L28-L82)
3. **Run matched whole episodes.** Use a fresh native thread and isolated source/store for every task/arm/repetition; keep the three turns in one thread; give the next fixed prompt only after normal completion, without reviewer hints or outcome-based repair. Pair at the *same task and repetition* and counterbalance order, serially on the same host. A small developmental pilot can reuse the historical two task types and two repetitions (eight runs), replacing on/off with native/Loci; keep the existing 120/360/240-second stage caps only if a new freeze explicitly selects them. Do not pair current runs with old graph-on/off or TypeScript results. [design:66-87,104-136](../../benchmarks/complete-work/design-v1/protocol.md#L66-L136), [schedule:1-13](../../benchmarks/complete-work/design-v1/schedule.json#L1-L13)
4. **Evaluate independently and blind.** Freeze task-specific terminal behavior and invariants before any model execution. Restore each final/stage snapshot and run evaluator-owned fixtures, never only agent-authored tests. Give a reviewer arm-masked final diffs, answers, test receipts, and source evidence; resolve claims and severe violations by one predeclared rubric. Check final correct completion first; retain corrected earlier mistakes and rework as stage observations. The Anvil oracle uses its own fixture and checks task-detail categories, graph-state preservation, API/page parity, and safe output. The Loci oracle runs child probes against the candidate checkout with a fresh store for exact `.direnv` exclusion, controls, and incremental removal. [design:138-166](../../benchmarks/complete-work/design-v1/protocol.md#L138-L166), [Anvil oracle:1-6,40-46](../../benchmarks/complete_work/oracles/anvil_oracle.md#L1-L46), [Loci oracle:1-5,104-220](../../benchmarks/complete_work/oracles/loci.py#L1-L220)
5. **Count the whole attempt.** Retain each scheduled row, including wrong answers, timeout, abort, malformed output, exhausted budget, uncalled Loci, source access violation, and recoverable tool errors. Record exact prompt/source/runtime/tool identities; full wall time and stage time; native shell/file and MCP operations with nested/outer distinction; raw model-visible outputs; source bytes and immutable content hash at delivery; repeated unchanged-source reads; test/repair cycles; provider input, cached input, output and inclusion semantics. Count every resource-consuming action in its arm. Missing source attribution, tool output, usage, or request telemetry is *unknown*, never zero or a successful efficiency result. Cumulative multi-turn usage is differenced once; observed response completions are a lower bound on model requests, not proof of all upstream retries. Provider cache hits and billed dollars cannot be inferred from a model slug. [design:130-136,168-194,196-221](../../benchmarks/complete-work/design-v1/protocol.md#L130-L221), [accounting:1-5,63-77,104-167](../../benchmarks/complete_work/accounting.py#L1-L167), [v1 read lineage:20-29,82-94](../../benchmarks/corpora/typescript-context-v1/read-lineage.md#L20-L94)
6. **Report pairs and limits.** Show terminal success and severe failures per task and arm before any aggregate. Include every scheduled attempt's elapsed and U/K/O tokens in resource totals; show total resources and per-correct measures only when all required telemetry is known, with zero successes yielding no efficiency winner. Report source delivery/coverage and Loci invocation separately from completion. Present each pair and task type, then a descriptively labelled pilot aggregate with uncertainty; two task types and two repeats do not support a population or significance claim. A new native/Loci decision rule must be frozen prospectively; the old graph-on/off Pareto and TypeScript gates cannot be imported as if they were this contrast. [design:196-249,261-264](../../benchmarks/complete-work/design-v1/protocol.md#L196-L264), [accounting:171-191](../../benchmarks/complete_work/accounting.py#L171-L191)
