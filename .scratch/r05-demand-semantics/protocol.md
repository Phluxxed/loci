# R0.5 prospective deterministic experiment

Outcome: compare R0.4 graph-free source acquisition, the smallest targeted demand-driven semantic mechanism, and R0.3 eager graph with decoupled reads. No main edits, production integration, V2, new evaluation framework or model evaluation campaign. Publish only the completed experiment branch.

## Fixed request policy

Retain authored entry requests and the exact R0.4 next_acquisition_query lexical scheduler. Every arm gets five acquisition calls, sixteen continuation calls, 128 KiB source/256 KiB packet-response soft admission caps, plus separately charged common inventory metadata. Demand spends its second slot on semantic_context(original entry query), a bounded bidirectional semantic-context request. Other arms retain their ordinary lexical or graph-enabled source acquisition. All requests are derived solely from entry query and actual delivered source/inventory, never context gold, missing coverage or scorer feedback. Worker receives no gold or baseline graph. No policy tuning after observed misses. A callable declaration must be uniquely established by observed source; ambiguity remains uncertainty.

Candidate reuse: full admitted path inventory to retain import alternatives; complete extraction of selected source; only needed local import/reexport/module closure; two semantic hops; keep full Rust touched-crate conditional module/control closure. Source-only index/search/read remain graph-free. Semantic question defers parsing/resolution until asked, may scan repository text globally for reverse candidates (charged and non-exhaustive under alias limitations), and may return supported source without semantic proof. Do not call source recovery reverse-caller proof: render.ts directly imports Anvil retrieval contracts from retrieve.ts.

Packet proof: emit complete relationship claims only with complete linked native support fitting 8 KiB source and16 KiB total MCP envelope. Otherwise omit that claim and state limitation. Symbol-targeted source extents may be paged with hash-bound references. Controls, module declarations, declared_possible configuration, unsupported families and incomplete closure remain explicit. Native sparse records/uncertainty are archived after each semantic question; do not reconstruct a full graph merely to score it.

## Schedule and gate

Targeted correctness/cost set: anvil_retrieval_limits and anvil_temporal_arguments (same Anvil source snapshot), rust_contained_optional_reexport, rust_unproven_contracts. The latter is an uncertainty control, not a positive proof requirement. Use two fresh repetitions, alternating arm order, plus immediate repeat of the full acquisition sequence per case in each worker. Compare R04 2b3b60e versus demand, and R03 b75fe58 versus demand, in the same existing benchmarks.architecture runner, explicit architecture flags and operation acquisition. All indexing/source exports/stores/temporary snapshots/caches isolated; no concurrent candidate measurement jobs.

Broader gate: if the targeted mechanism independently recovers any previously missing Anvil/Rust source evidence with nonzero valid semantic evidence and no false or unsupported claims, run all retained36 cases using the same candidate and policy. Assess Anvil five spans, Rust two missing spans and exact semantic links individually. Failure/partial recovery is a valid result; no guarantee of complete parity or need for an agent campaign. If that gate fails, stop after supported negative/inconclusive targeted finding.

## Accounting and observer

Archive actual first and repeated packets, sparse records, semantic work (scanned/parsed/copied paths and bytes, controls, cache hit/miss/validation, nested phase timing), source-reference pagination and all failures. Worker timing includes module imports, complete source inventory/hash passes, parsing/resolution, proof packing, source delivery, cache validation and archival; measure child CPU and process high-water RSS. Record resources/modules before any question to verify semantic work was deferred. Separate first/repeat operation totals and initial index cost. Controller proof validation has separate measured resource receipts; nested semantic timings are attribution, not additive cost. OS caches are not claimed cold; two repetitions are descriptive.

Independent frozen corpus loaders/scorers remain unchanged. New demand policy gets explicit native source/node/item/relationship shape validation, complete envelope byte checks, and native support join to the candidate's own sparse projection. Keep original packet-linked proof failures and distinct strict session-proof metric. Source coverage, semantic claims and unobserved task answers are distinct. Repeat equality is evaluated on capabilities and actual content; performance/cache metadata can differ. Negative checks must reject missing support, invalid bytes/hashes, malformed source/node links, stale source/control references, cross-root/escaped files, false unique resolution and promoted possible configuration. Preserve exact evaluator sources/manifests and independently replay with original stores/exports removed.

## Architectural limits

No broad capability is invented as an acceptance prerequisite. Existing resolver assumptions may force more module/control discovery than a single declaration; record that cost and the scope actually parsed. A valid sparse binding is not exhaustive reverse impact. Reading most of a tiny fixture is not evidence of selective repository-scale acquisition. No task-answer or agent-utility claims at this deterministic level.
