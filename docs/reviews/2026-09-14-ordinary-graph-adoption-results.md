# Ordinary graph adoption: retained results

The graph improvements are reachable and sometimes used. Ordinary discovery is
inconsistent, and counting only explicitly named graph tools gives the wrong
answer. In eight fresh Terra/high tasks on a fixed Anvil snapshot, four agents
discovered and called Loci. Two received relationships: one through
`loci_explore`, the other through two type-context gets. All eight recorded zero
`loci_graph_*` calls. One agent discovered the tools but both calls failed at the
repository catalog, so its shell fallback was a real runtime failure, not
skipped discovery.

The [frozen protocol](../../benchmarks/comparisons/ordinary-adoption-v1/protocol.md)
and [pre-outcome hashes](../../benchmarks/comparisons/ordinary-adoption-v1/freeze.json)
fix four source questions, eight ordinary attempts, four visibility diagnostics
and two primary functional checks. All 14 rows are retained in the
[execution ledger](../../benchmarks/comparisons/ordinary-adoption-v1/execution-ledger.json).
No row was retried, replaced, interrupted or removed; no operation, output or
five-minute budget was exceeded. Source, engine and installed Loci instruction
checks passed around each pair. The ten reserved post-change rows have not run.

| Condition | Attempts | Discovered/called Loci | Positive relationship delivery | Explicit graph-tool calls | Strictly complete answers |
| --- | ---: | ---: | ---: | ---: | ---: |
| Ordinary fresh delegates | 8 | 4 | 2 | 0 | 6 |
| Discovery-reminder diagnostics | 4 | 4 | 0 | 0 | 1 |
| Primary known-answer functional checks | 2 | 2 | 2 | 0 | 2 verified assertions; separate denominator |

The diagnostic task adds only a reminder to discover configured tools through
the deferred host surface. It demonstrates that the route can be noticed and
used. It is not an installed product correction or ordinary adoption evidence.
Neither this small comparison nor the primary checks establish causal benefit,
population rates, a model ranking or Claude behaviour in the inaccessible work
repository.

Every delegated final answer reaches the right main source/conclusion. The
strict coverage measure requires every predeclared detail, and the five
incomplete answers have omissions rather than identified material false
assertions. Browser runs 03/11 omit nonzero exit propagation. Checkpoint runs
08/09 omit projection-removal/conditional-update detail; 08 also omits initial
clear rejection conditions. Renderer 12 correctly lists the requested fields
but omits the frozen rubric's present-task heading and concrete line forms.
Calling those fields wrong would misrepresent the result. All exact quotes,
source references and assessments are retained under each
[run directory](../../benchmarks/comparisons/ordinary-adoption-v1/runs/).

The native operation stream supports several distinct findings:

- **Skipped discovery:** ordinary 02/03/04/06 make no deferred discovery request
  and zero MCP calls, despite reading the installed Loci skill. Run 03 explicitly
  announces that MCP tools are unavailable without attempting discovery. All
  four instructed diagnostics discover and invoke them. The installed skill
  says to prefer available MCP and explains unavailable fallback, but does not
  teach this host's `ALL_TOOLS` discovery check before taking that branch.
- **Instruction delivery boundary:** recorded developer messages for all eight
  ordinary delegates contain the Loci skill catalog but not the primary's
  explicit deferred-discovery instruction or Loci SessionStart hint. Tool and
  system inputs outside those recorded messages remain unverified. The
  [surface inventory](2026-09-14-adoption-surface-inventory.md) proves the
  installed ownership path and 21-tool availability, not universal attention or
  identical primary/delegate prompt delivery.
- **Runtime failure:** run 08's discovered search and grep both fail with
  `REPOSITORY_CATALOG_REPAIR_REQUIRED` and a pending-mutation reason. The agent
  correctly announces a temporary fallback. Its partner's calls succeed;
  later tasks and primary checks succeed without coordinator repair. The
  pending marker is absent before the final diagnostic pair. Keep this failed
  attempt in cost and adoption counts; it is not evidence of unwillingness to
  use Loci. The [ownership check](2026-09-14-adoption-catalog-failure.md)
  reproduces the same error while a legitimate writer holds the store-wide
  marker. Its existence is treated as crash evidence without a live-owner
  distinction. Run 08's failures occur inside its partner's first indexing
  call; that historical attribution remains an inference without marker-owner
  evidence.
- **Delivery is not answer use:** ordinary 01 receives four type edges, but its
  checkpoint answer is supported by exact service/store reads. Ordinary 07
  receives 12 type edges across two gets; an actual options-to-binding edge and
  its visible proof support a matching final-answer claim. That does not reveal
  internal cognition or prove the graph made the answer better.
- **Selection and budgets remain separate:** diagnostic 09 requests type
  context for six roots and receives no type relationships, with root/source
  budget omissions. Diagnostic 12 uses `explore(locate)`, which returns no
  relationships. Diagnostic 11 reaches the browser source with exact reads and
  never selects incoming impact. Increased discovery did not automatically
  select useful relationship retrieval.
- **Legitimate exact reads:** the renderer requires one function's source.
  Avoiding graph traversal is appropriate. The binding questions are also
  answered correctly without graphs in runs 02/10. Do not turn graph-call share
  into an answer-quality requirement.

The [capability probes](2026-09-14-adoption-capability.md) confirm useful binding
and browser relationships against exact source hashes. Primary checks 13/14
then independently verify native execution and full-exact model delivery in
Rowan's actual Astra/ultra host. Binding exploration resolves the right type,
but its multiline barrel proof contains only `export type {`; an exact file
read supplies the rest. The
[proof ownership trace](2026-09-14-adoption-reexport-proof.md) identifies the
TypeScript fallback to one support line in `exploration._Source.support`.
Browser impact supplies the caller, passed arguments,
exit handling and complete one-line import/re-export path. Both results retain
their non-exhaustive scope. These known-answer checks cannot estimate unprimed
primary adoption or be used as a cheaper-model comparison.

There is no general efficiency win here. Relative to the two ordinary attempts'
median, the single instructed browser diagnostic uses 20 native operations
versus 9, and 198,585 visible bytes versus 100,139.5. Binding uses 9 versus 11.5
operations with similar output bytes. Renderer uses 4 versus 7.5 operations but
more output bytes; checkpoint uses 18 versus 22 operations but more output and
provider input. Each comparison has only two ordinary samples and one
instructed diagnostic. The retained individual values, not a population
estimate, are the evidence. Source-byte totals count repeated native MCP spans;
unique source delivery and isolated shell source bytes were not measured.

The [ordinary accounting review](2026-09-14-adoption-accounting-review.md)
reconciles all native IDs, intervals, provider conditions and recorded access.
The [diagnostic access ledger](../../benchmarks/comparisons/ordinary-adoption-v1/runtime/diagnostic-access-ledger.json)
retains the same distinctions for runs 09–12: 35 successful MCP calls and zero
semantic edges, with all recorded targets and reads in scope.
The frozen observer conservatively leaves automatic graph-use qualification
false for seven ordinary rows because it treats several `pwd`/path-containing
shell chains as opaque. Manual review of their complete commands finds only
in-scope reads and no Loci CLI invocation; that supplemental evidence does not
rewrite the raw flag. Native terminal logging cannot detect silent upstream
omissions. Native assignment text is encrypted, so exact prompt use is a
coordinator attestation backed by schedule, agent path, model/effort and target
identity, not an independently recomputed plaintext hash. Whole native context
remains local; published artifacts retain normalized tool evidence and hashes.

The current compact graph-response fix is already live. Historical rejected
benchmarks remain rejected, as reconciled in the
[prior evidence map](2026-09-14-adoption-evidence-map.md). This audit warrants
specific discovery/runtime/proof dispositions; it does not warrant mandatory
graph calls, a new dashboard, or a claim that more graph use alone improves
answers. Concrete correction selection remains W1.5.2 in the same
Implementation Objective; the
[owned correction proposals](2026-09-14-adoption-correction-proposals.md)
state the exact behaviour and acceptance boundary for that decision.
